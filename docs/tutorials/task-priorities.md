# Task Priorities

Priority levels help you focus on what matters most. This tutorial explains how to use the priority system effectively to manage your workload.

## Priority Levels

The Kanban board uses three priority levels:

### High Priority

Indicated by a **red** badge, high-priority tasks:

- Require immediate attention
- Have urgent deadlines
- Block other work
- Have significant impact

Use sparingly to maintain meaning.

### Medium Priority

Indicated by an **amber/yellow** badge, medium-priority tasks:

- Are standard work items
- Have normal deadlines
- Represent your typical workload
- Should be the most common priority

This is the default priority for new tasks.

### Low Priority

Indicated by a **green** badge, low-priority tasks:

- Are nice-to-have items
- Have flexible deadlines
- Can be deferred if needed
- Include improvements and optimizations

## Setting Priority

### When Creating a Task

1. Open the task creation form
2. Find the **Priority** dropdown
3. Select the appropriate level
4. Complete the task creation

### When Editing a Task

1. Click on the task to open the detail view
2. Click the priority badge or dropdown
3. Select the new priority level
4. Changes save automatically

## Visual Priority Indicators

Priority is displayed through:

| Element | Display |
|---------|---------|
| Badge color | Red, Amber, Green |
| Card border | Subtle left border accent |
| Filter chip | Color-coded filter options |

### Color Meanings

```
High   = Red    (#EF4444) - Urgent, needs attention
Medium = Amber  (#F59E0B) - Normal, standard work
Low    = Green  (#10B981) - Flexible, can wait
```

## Priority Best Practices

### The Priority Pyramid

Your tasks should form a pyramid:

```
       /\
      /  \     Few High Priority
     /----\
    /      \   Some Medium Priority
   /--------\
  /          \  Many Low Priority
 /--------------\
```

### Avoid Priority Inflation

Common mistakes to avoid:

| Problem | Solution |
|---------|----------|
| Everything is high priority | Reserve high for true emergencies |
| Never using low priority | Not everything is equally important |
| Priority never changes | Reassess priorities regularly |
| Priority based on requester | Base on actual urgency and impact |

### When to Use Each Level

**High Priority:**
- Production issues
- Customer-blocking bugs
- Deadline within 24 hours
- Security concerns

**Medium Priority:**
- Feature work on schedule
- Non-critical bugs
- Standard improvements
- Deadline within a week

**Low Priority:**
- Technical debt
- Nice-to-have features
- Documentation updates
- Deadline is flexible

## Filtering by Priority

Use priority filters to focus your work:

1. **Morning Review:** Filter to High priority - what needs immediate attention?
2. **Daily Work:** Show High + Medium - your active focus
3. **Planning:** Show Low priority - what can be scheduled for later?

## Priority and Time Management

### The Eisenhower Matrix

Map priorities to the urgency/importance matrix:

|                | Urgent | Not Urgent |
|----------------|--------|------------|
| **Important**  | High | Medium |
| **Not Important** | Medium | Low |

### Time Allocation

Suggested time distribution:

- **High Priority:** 20-30% of your time
- **Medium Priority:** 50-60% of your time
- **Low Priority:** 10-20% of your time

## Dynamic Priority

Priorities should change as circumstances evolve:

1. **Escalation** - Low to High when deadline approaches
2. **De-escalation** - High to Medium when crisis resolves
3. **Regular Review** - Weekly priority assessment

> **Tip:** Review priorities at the start of each day. Yesterday's high priority may be today's medium.

## Team Considerations

When working with others:

- Agree on priority definitions
- Use consistent criteria
- Discuss when changing others' task priorities
- Consider stakeholder input
